# Wanna Try — product + UX revamp brief (user research, 2 Sep 2026)

Source: product research by Harshit, pasted into the working session. Kept verbatim as the reference for the next round of UI work; see `docs/product.md` for the current phased plan and ADRs 0012–0018 for what is already built.

WANNA TRY — COMPLETE PRODUCT + UI/UX REVAMP PROMPT

You are a world-class product designer, UX strategist, mobile app architect and consumer-product growth expert.

You are redesigning an existing mobile application called WannaTry.

Do NOT treat this as simply a UI redesign.

This is a product experience redesign based on a new product thesis.

⸻

1. PRODUCT THESIS

WannaTry is NOT:

* another Instagram
* another Pinterest
* another bookmarking app
* another Google Maps
* another travel app
* another generic AI chatbot
* another social media feed

The core product idea is:

People discover hundreds of things they want to experience, but most of them never actually do them. WannaTry remembers those intentions and helps users turn them into real experiences.

The product loop is:

DISCOVER → SAVE → REMEMBER → RECOMMEND → PLAN → TRY → COMPLETE → LEARN → DISCOVER

The entire product design must reinforce this loop.

The emotional feeling should be:

“These are all the things I want to experience in my life.”

The app should feel personal, inspiring, useful and slightly addictive in a healthy way — because it helps users experience more things, not because it encourages endless scrolling.

⸻

2. PRIMARY PRODUCT PROMISE

When someone asks:

“Why should I use WannaTry?”

The answer should be immediately understandable:

“You discover hundreds of things you want to do. WannaTry remembers them and helps you actually do them.”

Every major screen should support this promise.

⸻

3. CORE USER PROBLEM

People currently discover things through:

* Instagram
* YouTube
* Reddit
* WhatsApp
* Google
* blogs
* friends
* Pinterest
* short-form videos

They save or bookmark these things.

Then they forget about them.

Examples:

“I want to try that restaurant.”

“I want to visit that place.”

“I want to do that trek.”

“I want to try that pottery class.”

“I want to watch that movie.”

“I want to buy those shoes.”

“I want to try that experience.”

Six months later, most of these intentions are forgotten.

WannaTry should become the user’s external memory for experiences.

⸻

4. TARGET USER MENTAL MODEL

The user should think:

“Whenever I discover something I want to try, I put it into WannaTry.”

Later:

“What should I do this weekend?”

Open WannaTry.

WannaTry answers:

“Here are 3 things you’ve already wanted to try that make sense right now.”

This is the core habit.

⸻

5. IMPORTANT DESIGN PRINCIPLE

DO NOT solve the empty-state problem by creating a huge generic Explore feed.

Instead, combine:

PERSONALIZATION

DISCOVERY

CAPTURE

AI

The app should be useful even before the user has saved anything.

But it should become significantly more useful after the user starts saving things.

↓

↓

↓

⸻

52. FINAL DESIGN TEST

Before finalizing the redesign, ask:

Can a brand-new user understand WannaTry in 30 seconds?

Can they save their first item in under 60 seconds?

Does the app feel useful even with zero saved items?

Does the user have a reason to return next weekend?

Does the product help users actually experience things?

Is WannaTry clearly different from Instagram Saved?

Is the AI actually useful rather than decorative?

Does the interface feel premium without being complicated?

Can the product expand beyond travel?

Does every major feature strengthen the Save → Try loop?

If any answer is “no”, redesign that part.

⸻

FINAL PRODUCT DIRECTION

The final WannaTry experience should feel like:

Your personal bucket list for real life.

Not a feed.

Not a bookmark manager.

Not a travel planner.

Not an AI chatbot.

It is the place where all the things you think:

“I want to try that someday.”

finally become:

“I tried it.”

The visual design should make users WANT to fill their WannaTry with experiences, while the product intelligence should make them actually complete those experiences.

Build the UI around this emotional journey:

↓

“I WANT TO TRY THIS”

↓

SAVE IT

↓

“WANNA TRY”

↓

PLAN IT

↓

EXPERIENCE IT

↓

“I TRIED IT”

↓

“WHAT SHOULD I TRY NEXT?”

That final question is what keeps the product alive.
